# Рекомендуемый клиент: baresip (и настройка двух аккаунтов)

На дальнем телефоне (тот, что с тобой в поездке) нужен SIP-софтфон. После тестов мы
**рекомендуем [baresip](https://f-droid.org/packages/com.tutpro.baresip/)**
(`com.tutpro.baresip`, F-Droid): бесплатный libre-клиент, держит несколько аккаунтов и всегда
умеет page-mode `MESSAGE` (RFC 3428) — это критично для SMS.

## Почему baresip, а не Linphone

Linphone 6.2.x для нашей схемы **не подошёл**: его новый интерфейс не отправляет обычный
page-mode `MESSAGE` на произвольный номер (заточен под Flexisip/шифрованный чат), поэтому
**исходящие SMS из него не уходят**. Для звонков Linphone годится, для SMS — нет. baresip
проходит весь сценарий (звонок + входящая/исходящая SMS).

Подойдёт и любой другой SIP-софтфон, если он регистрируется по **UDP**, принимает **пустой
пароль**, позволяет указать **порт `:5062`** в адресе, и (для SMS) умеет page-mode MESSAGE
(MicroSIP, Zoiper и т.п.).

## Установка

F-Droid → **baresip** (`com.tutpro.baresip`) → установить.

## Настройка аккаунта (режим встроенного регистратора шлюза)

Меню **⋮ → «Профили»** → поле **«SIP URI или Новый аккаунт»** → ввести:

```
sip:s23@<IP-шлюза>:5062
```

→ **«+»** → включить тумблер **«Регистрация»** (интервал 900). Пароль, прокси, username — не
нужны (регистратор авторизацию не проверяет).

> ⚠ **Порт `:5062` обязателен прямо в AoR.** Без него baresip отправит REGISTER и MESSAGE на
> дефолтный `:5060`, где ничего не слушает.

`s23` — произвольное имя (в режиме регистратора оно не влияет на маршрутизацию: шлюз звонит
первой живой регистрации).

### Признак успеха

- В приложении-шлюзе: индикатор **SIP registration** зелёный, статус `phone registered`.
- В журнале шлюза: `phone registered: s23 @ <IP клиента>:<порт> lease=…`.
- В baresip аккаунт в спиннере горит **🟢 зелёным**.

## Схема «две SIM — один софтфон, два аккаунта»

Замысел: две SIM дома, в квартире с белым IP — одна в телефоне трека A (это приложение), вторая
в телефоне трека B (gsm2sip). Один дальний телефон держит **две SIP-регистрации** — по одной на
каждый шлюз.

| Аккаунт | AoR | Шлюз |
|---|---|---|
| 1 | `sip:s23@<IP-шлюза-A>:5062` | трек A (это приложение), эта SIM |
| 2 | `sip:100@<IP-шлюза-B>:5062` | трек B (gsm2sip), вторая SIM |

У обоих включить «Регистрация». В спиннере оба горят своим цветом: 🟢 — зарегистрирован,
🟠 — шлюз недоступен (выключен/уснул). Это и есть «две SIM — один софтфон».

> ⚠ **Один клиент на один AoR.** Если на том же номере с того же IP зарегистрируются два
> клиента, входящие достаются последнему зарегистрировавшемуся. Держи один софтфон.

## Короткий интервал регистрации — зачем

Таблица регистраций шлюза живёт в ОЗУ; после рестарта приложения/телефона она пустая. Чтобы
звонок пришёл, софтфон должен быстро перерегистрироваться. Это же освежает NAT-привязку при
работе через интернет. По умолчанию аренда шлюза 600 с (настраивается в приложении, раздел 3.2
справочника настроек), baresip обновляется ~раз в половину срока.

## Диагностика

- Аккаунт жёлтый/красный: порт `:5062` в AoR; транспорт **UDP**; нет ли VPN на дальнем телефоне;
  поднят ли шлюз (на треке A — поднят ли Shizuku, см. `shizuku-reboot.md`).
- Звонок есть, звука нет: это **способ захвата звука на шлюзе** (Cellular audio), не baresip —
  см. `settings-ru.md`, раздел 4.4.
