# Shizuku после перезагрузки (главный нюанс трека A без root)

Механизм перехвата звука вызова на Android 13+ требует прав уровня отладки, которые даёт
**Shizuku**. На **не-root** телефоне служба Shizuku **гаснет при каждой перезагрузке** — и шлюз
перестаёт работать (в приложении «Companion call setup incomplete», красные индикаторы), пока
Shizuku не поднят заново. Для роли «лежит дома, пока я в поездке» это главный эксплуатационный
риск: перезагрузка (обновление, разряд, сбой питания) разрывает связь до ручного вмешательства.

> ℹ️ Это именно про **перезагрузку**. Отдельная, более частая проблема — глубокий сон (Doze), когда
> телефон засыпал на ходу и ронял регистрацию софтфона, — **решена** встроенным wakelock
> (0.2.0-selfhost4): пока шлюз включён, служба держит CPU, и во сне регистрация не падает.
> Здесь остаётся только автозапуск Shizuku после ребута.

## Поднять Shizuku заново (не-root, нужен ПК с adb)

По USB или по Wi-Fi-adb:

```bash
# универсально: вычислить путь к нативному стартеру и запустить его
P=$(adb shell pm path moe.shizuku.privileged.api | sed 's/package://;s/base.apk//' | tr -d '\r')
adb shell "${P}lib/arm64/libshizuku.so"
# → "shizuku_server pid ..."
```

Путь вида `/data/app/~~<hash>/moe.shizuku.privileged.api-<hash>/lib/arm64/libshizuku.so`; при
переустановке приложения `<hash>` меняется, поэтому вычисляем его через `pm path` каждый раз.
Его же показывает сам Shizuku: «Запуск через соединение с ПК» → «Просмотр команды».

После запуска приложение-шлюз само подхватывает права → «Gateway ready», все индикаторы зелёные,
`SIP registration` — `phone registered`. На дальнем телефоне аккаунт этого шлюза станет 🟢.

**Без ПК** Shizuku запускается через системную **«Беспроводную отладку»** прямо на телефоне
(Shizuku → «Запуск через беспроводную отладку»).

## Диагностика состояния по adb

```bash
adb shell ps -A | grep -i shizuku        # есть ли процесс shizuku_server
adb shell cat /proc/net/udp6             # строка с портом :13C6 (=5062) = SIP-сервер слушает
adb logcat -s VoiceSipAgent VsaTap VsaPrivileged
```
В приложении — раздел «Состояние (Health)»: всё зелёное и «Gateway ready».

## Решения для необслуживаемой работы

1. **Root (рекомендуется, если аппарат рутуется).** В Shizuku разблокируется переключатель
   **«Запускать при загрузке» (Start on boot)** — работает **только с root**. Shizuku
   поднимается сам сразу после включения, без ПК и без беспроводной отладки. Плюс включи
   автозапуск самого приложения и сними оптимизацию батареи → после любого ребута встают оба.
   **Код приложения не меняется** — оно общается с Shizuku одинаково, запущен тот от root (uid 0)
   или от отладки (uid 2000).
   > Разок проверь живым звонком на рутованной трубке самое тонкое место — захват телефонного
   > аудио под uid 0.
2. **Не перезагружать телефон-шлюз**, держать на стабильном питании и Wi-Fi. Следить, чтобы не
   засыпал и не уходил с сети (иначе его IP становится недоступен и аккаунт на дальнем телефоне
   желтеет).
3. **Маленький постоянный ПК/SBC рядом** (например, одноплатник), который по USB или Wi-Fi-adb
   выполняет команду запуска Shizuku при своей загрузке — тогда даже без root шлюз
   самовосстанавливается.

## Почему так

Запуск привилегированной службы с правами отладки по замыслу Android требует физического доступа
к разблокированному телефону и не переживает перезагрузку — именно это и делает механизм
безопасным (удалённо «подсадить» его жертве нельзя). Обратная сторона — ручной перезапуск после
ребута. Root снимает ограничение штатно.
